연구 제안 (초안)

시뮬레이션 기반 3DGS 장면의
Physical Segmentation

3DGS 장면을 물리 시뮬레이션이나 robot manipulation에 쓰려면, 장면을 실제로 함께 움직이는 단위(physical unit)로 segmentation해야 한다. 기존 sim-ready 연구들은 SAM 기반의 시각적 segmentation 결과를 고정된 입력으로 사용하기 때문에, segmentation이 물리적으로 맞지 않아도 이를 바로잡는 단계가 없다. 본 연구는 segmentation 후보를 가설로 두고, 짧은 상호작용을 시뮬레이션으로 재현해 실제 관찰과 가장 잘 맞는 segmentation을 선택하는 방법을 제안한다.

권상민 · 2026년 10월 · 초안 (관련 연구는 2026년 9월 arXiv까지 확인)

문제

시각적 segment와 실제로 함께 움직이는 단위가 다르다. 손잡이가 따로 잡히거나(over-segmentation) 컵과 받침이 하나로 묶이면(under-segmentation) 시뮬레이션 결과가 틀어진다.

방법

Segmentation 후보를 가설로 두고, 관찰된 상호작용을 시뮬레이션·렌더링으로 재현해 가장 잘 맞는 가설을 선택한다.

기여

Segmentation을 물리적으로 검증·수정하는 절차와, 이를 물리적 결과로 평가하는 지표를 제시한다.

1연구 동기

3DGS 장면을 물체 단위로 나누고, physical property를 부여하고, 시뮬레이터에 넣어 로봇이 다루게 하는 연구가 빠르게 늘고 있다. 이 pipeline에서 object segmentation은 거의 항상 첫 단계이고, 그 결과가 이후 모든 단계의 전제가 된다.

  • Segmentation 기준이 appearance다: 대부분 SAM 같은 2D mask를 3D Gaussian으로 lifting한다.
  • 이후 단계에서 segmentation을 수정하지 않는다: physical property 추정, amodal completion, sim-ready scene 구성 모두 segmentation 결과를 그대로 입력으로 쓴다.
  • 물리적 역할은 사람이 지정한다: 3DGS 물리 연구에서는 고정 영역 같은 boundary condition을 bounding box로 직접 지정하는 경우가 많다.

즉, segmentation이 시뮬레이션 결과를 좌우하지만 segmentation 자체는 appearance 기준이거나 수작업으로 정해진다. 본 연구는 이 부분을 다룬다.

2관련 연구

3DGS에서 physical AI로 이어지는 각 단계마다 연구가 있지만, segmentation은 모두 appearance로 정하거나 주어진 것으로 받는다. Segmentation이 물리적으로 맞는지 확인하는 단계는 없다.

3문제 정의

Physical unit은 상호작용을 받을 때 하나의 rigid body처럼 함께 움직이는 Gaussian들의 최대 집합이다. Unit 사이에는 fixed attachment, contact/support, independent 중 하나의 relation이 있고, 환경에 고정된 unit은 static이다. 시뮬레이터가 필요로 하는 정보는 이 unit과 relation이다.

시각적 segment와 physical unit은 세 가지 방식으로 어긋난다.

유형예시뮬레이션에서 생기는 문제
Over-segmentation머그 손잡이가 따로 잡힘손잡이만 떨어지거나, 손잡이를 잡으면 손잡이만 들림
Under-segmentation컵과 받침이 하나로 잡힘컵을 들면 받침도 같이 들림
고정 누락·과잉벽에 걸린 액자, 화분에 심긴 줄기액자가 떨어지거나, 고정된 부분이 잘린 면처럼 보임

기존 지표로는 이 오류가 잘 드러나지 않는다. Segmentation은 보통 학습 시점에서 2D mIoU로 평가한다. 위 오류는 대부분 contact 영역과 가려진 영역에서 생기므로, 물체를 움직였을 때 비로소 나타난다.

정지 상태만 봐서는 구분할 수 없는 경우가 있다. 다리 위에 얹혀 있는 의자 좌판과 고정된 좌판은 정지 상태에서 같게 보이고, 밀거나 들어 올려야 구분된다. 따라서 segmentation에 상호작용 정보를 활용할 필요가 있다.

4제안 방법

Segmentation 후보를 가설로 두고, 관찰된 상호작용을 시뮬레이션으로 가장 잘 재현하는 가설을 선택한다 (segmentation-by-simulation). 입력은 3DGS 장면과 짧은 상호작용 관찰이다. 상호작용 관찰은 물체 몇 개를 손으로 밀거나 든 전후의 multi-view 촬영, 또는 그 과정의 짧은 영상이다.

  1. 후보 생성: SAGA·GARField 방식의 multi-scale segmentation으로 merge tree를 만든다. Tree를 자르는 위치와 인접 unit 사이의 relation label 조합이 하나의 가설 H가 된다. VLM은 "손잡이는 서랍에 붙어 있다" 같은 상식으로 각 가설에 prior를 준다. 이 단계는 search space를 줄이기 위한 것으로, 기여에는 포함하지 않는다.
  2. Static pruning: 따로 떼었을 때 contact만으로 버틸 수 없는 가설은 짧은 중력 시뮬레이션으로 걸러내고, attachment나 같은 rigid body로 바꾼다.
  3. 시뮬레이션 기반 검증 (핵심): 남은 가설마다 관찰된 행동을 시뮬레이션으로 재현한다. 손이 닿은 unit은 관찰된 trajectory를 따라 움직이고, 나머지는 가설의 relation에 따라 함께 움직이거나(attachment), 마찰로 끌려가거나(contact), 그대로 있는다(independent·static). 결과를 3DGS로 렌더링해 실제 관찰과 비교한다.
  4. Export: 선택된 가설을 시뮬레이터 asset(rigid body, fixed joint, collision proxy)으로 내보낸다. Gaussian appearance는 각 rigid body에 붙인다.

가설 선택은 다음 목적식을 따른다.

H* = argminH [ minθ D( R(Sim(G, H, θ; a)), O ) + λ·k(H) − μ·log p(H) ]
  • G는 3DGS 장면, H는 segmentation·relation 가설, θ는 continuous parameter(pose, friction, mass 비율), a는 관찰된 행동, R은 3DGS rendering, O는 관찰이다.
  • k(H)는 가설의 DoF다. Over-segmentation이나 deformable 가설처럼 DoF가 많은 가설은 거의 모든 움직임을 맞출 수 있으므로 penalty를 준다.
  • p(H)는 VLM prior다. 관찰만으로 구분되지 않는 가설 사이에서 tie-breaker 역할을 한다.
  • 바깥의 argmin은 prior 순서의 beam search(discrete), 안쪽의 min은 continuous optimization이다. Segmentation은 discrete 변수라 gradient로 풀 수 없기 때문이다.
  • 계산 비용의 핵심은 "가설 수 × 시뮬레이션 × 렌더링"을 GPU에서 한 번에 평가하는 것이다.

5Trajectory clustering과의 차이

움직임이 관찰되면 trajectory가 비슷한 Gaussian끼리 묶는 방법(SplArt, DeGSS, MotionBits)으로도 segmentation할 수 있다. 시뮬레이션 기반 검증은 이 방법과 다음 세 가지 점에서 다르다.

  • Contact와 attachment를 구분한다. 아래 책을 밀면 위 책도 마찰 때문에 함께 움직인다. Trajectory clustering은 두 책을 하나로 묶지만, 시뮬레이션에서는 contact 가설도 같은 관찰을 설명할 수 있음을 알 수 있다. 이 경우 prior로 선택하거나, 두 가설을 구분할 수 있는 다음 행동(위 책 들기)을 제안한다.
  • Held-out interaction으로 검증할 수 있다. 선택된 segmentation으로 다른 상호작용의 결과를 예측할 수 있으므로, label 일치도 외에 물리적 타당성을 평가할 수 있다.
  • 결과를 시뮬레이터에서 바로 사용할 수 있다. Trajectory clustering 결과는 label이므로, relation과 joint로 변환하는 단계가 따로 필요하다.

Trajectory clustering은 주요 baseline으로 실험에 포함한다.

6기여

기존 연구에서 고정 입력으로 쓰이던 segmentation을, 물리적 관찰로 검증하고 수정하는 대상으로 다룬다는 점이 주된 기여다.

  1. 문제 정의와 평가: Physical unit segmentation을 상호작용 결과로 정의하고, 이를 평가하는 지표(grasp-and-lift consistency, held-out interaction prediction)와 정답이 있는 synthetic benchmark를 만든다.
  2. 방법: Segmentation 가설을 시뮬레이션과 렌더링으로 검증하는 segmentation-by-simulation. DoF penalty와 prior로 identifiability 문제를 다룬다.
  3. 연결: 결과를 물리 시뮬레이터에 바로 넣고, robot manipulation task 성공률로 효과를 보인다.

7실험 설계

기존 2D mIoU에 더해, segmentation을 물리적 결과로 평가하는 지표를 사용한다. 이 지표 설계도 기여에 포함된다.

데이터

  • Synthetic: 물리 시뮬레이터로 만든 tabletop scene. PartNet-Mobility와 PhysXNet asset으로 정답 rigid body·joint를 두고, photorealistic rendering으로 3DGS를 학습한다. 상호작용도 정답 scene에서 시뮬레이션해 만든다.
  • Real: 휴대폰으로 찍은 before/after 촬영(손으로 밀기·들기). 공개된 3DGS-CD의 before/after rearrangement 데이터도 활용을 검토한다.

8연구 계획

첫 단계에서는 기존 segmentation 방법이 실제로 물리적 오류를 얼마나 만드는지 먼저 측정한다. 기간은 예상치이며, pilot 실험은 아직 수행하지 않았다.

  1. Pilot (2~3주): 시뮬레이터 scene 5~10개(손잡이 머그, 쌓인 책, 컵과 받침, 화분, 벽 부착물)를 만든다. Gaussian Grouping·SAGA로 나눈 segment를 각각 rigid body로 올리고, grasp-and-lift 실패율을 측정한다.
  2. Static 단계 (약 1개월): Merge tree 후보, VLM prior, static pruning을 구현하고 synthetic scene에서 unit·relation accuracy를 측정한다.
  3. 시뮬레이션 기반 검증 (1~2개월): Synthetic interaction으로 가설을 선택하고, 가설들을 GPU에서 batch로 평가하도록 구현한다.
  4. Real data (약 1개월): Before/after 촬영으로 검증하고 held-out interaction prediction을 측정한다.
  5. Manipulation 실험과 논문 작성: Robot manipulation 성공률을 측정하고 논문을 쓴다. 작성 직전에 관련 연구를 다시 조사한다.

첫 논문은 rigid body와 attachment·contact relation으로 범위를 좁힌다. Deformable relation은 DoF penalty가 제대로 작동하는지 확인한 뒤 추가한다.

9위험 요소와 대응

가장 큰 위험은 identifiability, 즉 한 번의 관찰로 가설이 하나로 정해지지 않는 경우다.

10FAQ

SAM mask를 잘 쓰면 되지 않나?
시각적 segment와 physical unit은 정의가 다르다. 오류가 contact 영역에 몰려 있어 mIoU로는 잘 보이지 않는다. Pilot 실험의 grasp-and-lift 실패율로 보일 계획이다.
움직임이 있으면 trajectory clustering으로 충분하지 않나?
Clustering은 마찰로 끌려간 것과 붙어서 함께 움직인 것을 구분하지 못하고, 새 상호작용을 예측하지 못한다. Baseline으로 비교한다.
HoloScene·SimRecon과 무엇이 다른가?
해당 연구들은 segmentation을 고정한 채 pose와 geometry를 보정한다. 본 연구는 segmentation 자체를 보정하며, 두 접근은 함께 사용할 수 있다.
로봇 없이 가능한가?
사람 손으로 한 상호작용을 before/after로 촬영하고, 시뮬레이터에서 synthetic 실험을 한다. 로봇이 상호작용할 위치를 스스로 고르는 active selection은 로봇이 있을 때의 확장이다.
왜 그래픽스 연구인가?
가설마다 시뮬레이션과 렌더링을 반복하므로 GPU 기반 simulation·rendering 효율이 중요하고, 관찰과 비교하는 analysis-by-synthesis 과정은 렌더링 문제와 직결된다.
Diffusion 같은 학습 기반 방법은 왜 쓰지 않나?
Scene 수준의 physical segmentation 정답 데이터가 거의 없다. 먼저 merge tree 후보로 충분한지 확인하고, 부족한 사례가 쌓이면 학습 기반 hypothesis 생성기를 추가한다.

11향후 연구

첫 논문의 "segmentation 가설 + 시뮬레이션 검증" 구조를 유지하면서 다음 방향으로 확장한다.

  • Active interaction: 모호한 가설을 가장 잘 구분하는 행동(밀기, 당기기, 들기)을 로봇이 스스로 선택한다.
  • Uncertainty 유지: 하나의 segmentation 대신 여러 가설을 확률과 함께 유지하는 표현으로 확장한다.
  • Task-conditioned segmentation: 옮기기, 잡기, 변형 등 task에 따라 필요한 단위가 다르다는 점을 다룬다.
  • Deformable·material: Deformable relation을 추가하고 KnockGS·PhysReal 같은 physical parameter 추정과 결합한다. Sim-ready 연구 대부분이 rigid body만 다루므로 이 확장 자체가 차별점이 된다.
  • 학습 기반 hypothesis 생성: Merge tree에 정답이 없는 사례가 쌓이면 diffusion 같은 generative prior를 hypothesis 생성기로 추가한다. 검증은 계속 시뮬레이션이 맡는다.

12논의 사항

  • 첫 논문 범위를 rigid body와 attachment·contact relation으로 좁히는 것이 맞는지, 처음부터 deformable을 포함하는 것이 나은지
  • Active interaction을 위한 robot arm이나 촬영 장비를 언제부터 사용할 수 있는지
  • Target venue를 graphics, vision, robotics 중 어디에 맞출지 (평가 비중이 달라짐)

참고 문헌

본문 표에 없는 논문만 적었다. 모두 2026년 10월에 검색으로 존재와 요지를 확인했으며, 인용 전에 원문을 다시 확인해야 한다.

  • Segment Any 3D Gaussians (SAGA)
  • MotionBits: 2D video의 rigid motion 단위 segmentation, MoRiBo benchmark
  • KnockGS: 상호작용 응답으로 elasticity·density 보정
  • 3DGS-CD: rearrangement 전후 change detection
  • PhysX-3D / PhysXNet: part 단위 physical annotation 데이터
  • IAAO (CVPR'25): 상호작용을 통한 articulated object 이해
  • RISeg: 로봇 push 기반 2D segmentation
  • Kreber et al. (ICCV'25): 관찰에 맞춘 diffusion 기반 articulated object 생성
  • SimuScene: single image, 물리 엔진을 진단 도구로 사용
